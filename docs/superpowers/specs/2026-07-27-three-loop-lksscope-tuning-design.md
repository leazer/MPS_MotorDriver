# 三环 LKS Scope 在线调参与监视设计

## 目标

在 `feat/motor-driver-can-node` worktree 中扩展 `debug.lksscope`，使操作者可以通过 LKS Scope 数值变量表直接修改电流环、速度环、位置环及相关保护参数，并同时观察三环运行量、电机运行状态、运行模式、控制设定和传感器原始/标定后数据。

在线参数仅保存在 RAM 中，复位或重新上电后恢复 `motor_params.h` 中的编译默认值。图表与现有曲线由用户自行配置，本次改动不增加、删除或重排曲线变量。

## 已确认约束

1. 采用方案 A：集中 RAM 参数块和集中运行快照。
2. 参数由 LKS Scope 直接写入，下一次对应环路执行时生效，不需要额外提交命令。
3. 不增加未知的绝对硬安全上限，也不自动把用户写入值修正到推测的安全范围。
4. 现有故障锁存、PWM 关断和状态机处理流程保留；其过流和采样相关判定阈值开放在线调整。
5. 环路执行分频、PWM 频率、极对数、编码器方向等结构性参数保持编译期固定，避免在线改变离散控制周期或坐标定义。
6. 保留 worktree 中已有的未提交改动。提交时只暂存本任务明确创建或修改的文件。

## 架构

新增 `motor_tuning.h/.c`，定义一个具有外部链接、稳定调试符号名的全局参数块：

```c
extern volatile motor_tuning_t g_motor_tuning;
```

`motor_tuning_init()` 在电机控制各环初始化前调用一次，用 `motor_params.h` 的宏填充全部默认值。控制与保护代码不再在运行路径中直接读取相应宏，而是读取 `g_motor_tuning` 的对应字段。

新增一个具有稳定符号名的运行快照：

```c
extern volatile motor_loop_debug_t g_motor_loop_debug;
```

各数据的现有所有者负责发布对应快照字段：电流环发布 D/Q 轴数据，速度环发布速度数据，位置环发布位置数据，ISR 发布保护判定数据。电机状态、运行模式、控制设定和编码器数据若已有稳定、权威的 RAM 对象，则变量表直接引用该对象，避免产生第二份可能不同步的数据；只为缺失的三环中间量增加集中快照字段。

所有在线字段使用与 Cortex-M4 原生字长匹配的 `float`、`int32_t`、`uint32_t`、`uint16_t` 或 `uint8_t`。LKS Scope 按单字段修改；不提供多字段事务语义。

## 在线参数

### 电流环

- Id Kp、Id Ki
- Iq Kp、Iq Ki
- Id 积分限幅、Iq 积分限幅，单位 V
- Id 输出限幅、Iq 输出限幅，单位 V

Id/Iq 的限幅分别存储，默认值均来自现有公共电流环限幅宏，允许物理调试时单独调整 D/Q 轴。

### 速度环

- 加速 Kp
- 制动 Kp
- Ki
- 积分限幅，单位 A
- Iq 输出限幅，单位 A
- 摩擦前馈，单位 A
- 目标斜坡，单位 `rad/s²`

速度环运行时直接读取这些字段。位置模式中速度环输出与位置前馈合成后的 Iq 限幅也读取在线 Iq 输出限幅，避免存在两个看起来相同但效果不同的限幅。

### 位置环

- Kp
- 电气速度输出限幅，单位 `rad/s`
- 最大目标速度，单位 `mdeg/s`
- 最大跟踪误差，单位 `mdeg`
- 最大命令位置绝对值，单位 `mdeg`
- 轨迹外推时间，单位 ms
- 静止位置摩擦前馈，单位 A
- 运动摩擦前馈，单位 A
- 摩擦补偿误差死区，单位 `mdeg`

CAN 运动命令入口与位置环本体读取同一组最大命令位置、最大目标速度和最大跟踪误差参数，避免入口接受规则与控制环故障规则不一致。

### 过流与采样保护

- 相电流过流阈值，单位 A
- 过流连续命中次数，单位 PWM tick
- 三相电流和不平衡阈值，单位 A
- 不平衡连续命中次数，单位 PWM tick
- 低侧采样消隐时间，单位 PWM tick
- 连续无效采样故障次数，单位 PWM tick

这些字段取代 ISR 和采样重构运行路径中的对应宏。现有计数、故障位和关断动作不变。

## LKS Scope 配置

只修改 `debug.lksscope` 的 type 7 数值变量表：

1. 增加 `g_motor_tuning` 的全部可写参数，描述中明确所属环、含义和单位。
2. 增加 `g_motor_loop_debug` 的新增运行快照字段。
3. 保留现有电机状态、编码器、采样、PWM 和故障变量。
4. 不修改 type 8 曲线表。
5. 保留用户当前保存的窗口布局、串口配置、采样周期和代码变量映射路径。
6. 构建完成后以生成的 ELF/AXF 核对符号。若 LKS Scope 保存具体 RAM 地址，则只用当前固件地址更新新增条目，不回退用户的其他界面改动。

## 数据流

1. 启动时 `motor_tuning_init()` 将编译默认值复制到 `g_motor_tuning`。
2. LKS Scope 通过调试接口读写 `g_motor_tuning` 的单个字段。
3. 电流、速度、位置和保护代码在各自执行周期读取当前字段，因此修改在下一次对应计算中生效。
4. 各环完成计算后发布中间量和限幅状态到 `g_motor_loop_debug`。
5. LKS Scope 数值变量表以 10 ms 周期显示参数、快照和现有权威状态对象。

## 异常与操作语义

本功能不对写入值施加推测的上下限，也不拒绝零、负数、非有限浮点数或相互矛盾的参数。操作者负责写入值的物理合理性。复位是恢复所有编译默认值的统一方法。

现有驱动故障、过流、采样故障、位置跟踪故障和 CAN 故障处理仍按原状态机执行，但开放后的阈值会直接影响故障触发条件。

## 测试与验证

1. 先增加失败的静态与主机测试，要求集中参数符号、初始化默认值和运行快照接口存在。
2. 主机测试修改 RAM 参数，验证电流环、速度环、位置环输出和限幅结果随修改立即变化。
3. 保护测试修改过流、去抖、采样消隐、无效采样和不平衡阈值，验证现有保护判断读取在线值。
4. XML 静态测试验证所有必需参数和运行变量都存在于数值变量表，名称无重复，type 8 曲线集合保持不变。
5. 运行相关主机测试、全部 motor-control 静态测试和 `git diff --check`。
6. 构建目标固件，并从 ELF/AXF 符号表确认 `g_motor_tuning`、`g_motor_loop_debug` 及变量表引用的现有状态/传感器符号均可解析。

## 非目标

- 不保存调参结果到 Flash。
- 不生成或调整图表。
- 不改变 PWM 频率、环路分频、极对数或编码器方向。
- 不重新设计故障状态机。
- 不增加远程 CAN 调参协议。
