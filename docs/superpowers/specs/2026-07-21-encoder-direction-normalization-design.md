# 编码器方向归一化与速度环实机恢复设计

## 目标

修正 V2 电机相序与 MA600A 原始计数方向不一致造成的控制坐标错误，使正向开环电角度、编码器电角度、编码器速度、正向 Iq 力矩和速度环目标使用同一正方向。在不破坏已经通过的电流采样重构与 ±500mA 电流环结果的前提下，恢复速度闭环并为位置环提供可靠的机械角坐标。

## 已确认的根因证据

- 2026-07-21 复跑 `tests/stage5_bench.py COM9`，±50/100/200/500mA 八点全部通过；最大 Iq 偏差 3mA，最大 |Id| 1mA，`valid_mask=0x07`，invalid/freeze/fault 均未增长。
- `mc_speed 10` 时目标与命令均为 `+1047mrad/s`，反馈长期接近零，速度 PI 最终请求 `+1500mA`；电流反馈约 `+700mA`，编码器位置基本不动。
- 自由轴条件下，`mc_cur +200 enc` 与 `mc_cur -200 enc` 分别只移动约 10～12°机械角后停止，呈现错误转子坐标产生的电磁弹簧特征。
- 权威方向对拍中，`mc_open 1000 +60 ramp` 使编码器 corrected unwrap 从 `+233` 连续下降到 `-38536`，电速度反馈约 `-5.5～-7.0rad/s`；`mc_open 1000 -60 ramp` 则产生约 `+6～7rad/s` 反馈。
- 因此正向电角度斜坡与 MA600A 原始计数方向相反。现有 `encoder_service` 直接用 `corrected-zero` 计算电角度并用 corrected unwrap 差分计算速度，导致角度和速度符号同时错误。速度 PI 算法本身不是根因。

## 方案比较

### 方案 A：在编码器服务控制量边界统一方向（采用）

增加集中式编码器方向常量，保持 `raw16`、`corrected_raw16` 和校准表索引的硬件语义不变；在从位置生成控制电角度、从位置差生成机械/电气速度时应用方向。CURRENT、SPEED 和后续 POSITION 模式自然消费同一坐标。

优点是修改边界单一、不会破坏三相 PWM/ADC 映射，且能同时修复编码器电流模式、速度环和位置环。风险是必须明确哪些诊断字段是原始硬件方向、哪些是归一化控制方向，并用测试锁定。

### 方案 B：交换 U/W 相或 PWM 通道（不采用）

可让电机正向与编码器计数方向一致，但会改变已经验证的 V2 相序、电流通道与低侧重构关系，需要重做全套电流极性和采样验证，风险过高。

### 方案 C：仅在速度环把反馈取反（不采用）

改动最小，但 CURRENT enc 模式的转子角仍错误，位置环也会继续使用错误坐标，形成多个局部补丁。

## 控制坐标语义

- `raw16`：MA600A 原始单圈计数，0..65535，保持硬件方向。
- `corrected_raw16`：应用非线性校准后的原始单圈位置，仍保持硬件方向。
- `raw_unwrapped`、`corrected_unwrapped`：保留传感器诊断语义，不在本修复中静默改变含义。
- 控制机械位移：由方向归一化后的 `zero-to-position` 差得到，正方向与正开环电角度一致。
- `elec_mrad`：校准后位置扣除零点、应用编码器方向、乘极对数并归一化到 0..2π。
- `raw_elec_mrad`（若 LKS 调试任务加入）：跳过非线性表，但使用相同零点、极对数和方向。
- `speed_mech_mrad_s`、`speed_elec_mrad_s`：窗口差分速度乘同一个方向常量；正开环斜坡必须得到正速度。

方向常量放在集中参数层，值取 `-1`。位置到电角度的换算使用无符号环绕差，避免 0/65535 跨越处分支错误；速度在现有有符号 unwrap 差分结果上乘方向。

## 实现边界

1. 在 `motor_params.h` 增加方向常量及编译期语义注释。
2. 在 `encoder_service.c` 抽取“已选位置到归一化电角度”的纯计算路径，raw 与 corrected 均可复用。
3. 窗口速度发布时应用相同方向，保持机械速度与电气速度关系为 `omega_e = pole_pairs * omega_m`。
4. 不修改 V2 `PWM_PHASE_U/V/W_TMR_CHANNEL`、SOA/SOB/SOC 映射、电流重构极性、Id/Iq PI 参数、16kHz PWM 或 CCR4=5264 采样策略。
5. 不在本修复中加入位置环实现；位置环在速度环实机通过后单独设计和实施。
6. 与正在进行的 LKS Scope 调试改动兼容：若 `raw_elec_mrad` 已由该任务实现，方向归一化必须作用于 raw/cal 两条电角度路径；不覆盖其未提交工作。

## 速度环安全策略

- 首次修复验证仍以已经实机通过的 ±500mA 为安全电流范围。
- 为速度模式增加独立的初始 Iq 限制 `SPEED_IQ_LIMIT_A=0.5f`，不降低 `mc_cur` 的全局 `IQ_MAX_A=1.5f` 命令能力。
- 速度环积分和输出限幅使用速度模式限制，避免启动或方向错误时请求未经台架验证的 1.5A。
- 依次验证 10、60、200rpm_elec；只有方向、稳态误差、采样质量和停机都通过后，才另行决定是否把速度模式限流提高到 1.5A。
- 每个实机段都检查 fault、invalid frame、PI freeze、Id/Iq、速度反馈，并以 `mc_stop`、EN=LOW、PWM=50% 结束。

## 测试与验证

### 主机与静态测试

1. RED：正向 raw 计数减少时，方向归一化后的电角度和速度应为正；当前实现失败。
2. GREEN：覆盖正/负方向、0/65535 跨越、7 极对数、raw/cal 两条电角度路径和机械/电气速度符号。
3. 现有编码器、电流采样、电流重构、速度环静态测试全部通过。
4. Keil clean build 必须 0 Error、0 Warning。

### 板端门禁

1. 烧录后确认 DISABLED、fault=0、EN=LOW、CCR1/2/3=2812、CCR4=5264、VBUS 约 12V、编码器标定 valid。
2. 重新执行 `mc_cal`，再跑权威 ±500mA 电流环矩阵，确认方向修复没有破坏内环。
3. 开环方向对拍：`mc_open 1000 +60 ramp` 必须得到正的归一化电速度；负命令得到负反馈。
4. `mc_cur +200 enc` 与 `-200 enc` 在自由轴上必须产生相反的持续力矩方向，不再只移动小角度后形成静态电磁弹簧；测试时间保持短并立即关断。
5. 速度环依次运行 `mc_speed 10`、`60`、`200`，要求反馈方向正确、Iq 不超过 500mA、无 fault/invalid/freeze，稳态误差目标小于 5%。
6. 最终主动查询并记录安全态。

## 完成条件

- 根因由自动测试和正反实机对拍共同覆盖。
- 电流环 ±500mA 回归不退化。
- 速度环至少在正负 60rpm_elec 和正向 200rpm_elec 下可持续稳定运行，方向正确，无故障，安全停机正常。
- 调试记录写明参数、实测响应、未覆盖电流/速度范围及位置环的前置条件。
